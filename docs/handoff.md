## 이 문서를 읽는 Codex에게

이 문서는 선생님과 나눈 대화를 정리한 출발점이다. 실제 설치나 앱 완성을 뜻하지 않는다. 먼저 현재 컴퓨터와 작업 폴더, 기존 설치 상태를 확인하고 관찰 결과를 선생님께 이해하기 쉽게 설명한다. 확인 전 RAM, GPU, 운영체제 버전이나 모델 성능을 가정하지 않는다. 이미 있는 설정과 파일을 함부로 덮어쓰지 않는다.

선생님은 한국의 고등학교 영어교사이자 교육기술 실천가다. 바이브 코딩으로 수업용 웹앱을 만들어 왔으며, 교육적 목적과 실제 사용자 흐름, 완성도 높은 디자인을 중요하게 생각한다. 전문 용어를 피할 필요는 없지만 처음에는 쉬운 말과 예시로 설명한다. 선택지가 필요할 때 장단점과 추천을 함께 제시한다. 장황한 계획만 반복하지 말고, 확인 가능한 작은 결과를 만들고 검증하며 진행한다.

## 프로젝트의 목적

교사와 학생이 활용할 수 있는 학교 AI 작업실을 단계적으로 만든다. 교사의 성적 분석과 영어 수업 도구, 학생의 탐구와 AI 제작, 음성·영상 활동을 지원한다. 처음에는 개인 기기에서 작동하는 작은 도구로 시작하고, 검증 후 다른 교사에게 배포하거나 학교 내 공동 사용으로 확장할 가능성을 살핀다.

핵심 교육 원칙은 학생이 질문하고, 판단하고, 검증하며, 스스로 수정할 주도권을 갖는 것이다. AI가 답을 대신 완성하기보다 적절한 힌트를 제공하고, 필요에 따라 지원을 줄인다. 학생이 AI의 제안을 수용하거나 거절하고 그 이유를 생각할 기회를 만든다. 학생의 수준과 선택권을 고려한다.

## 현재 결정과 미결 사항

- 시작 후보: 윈도우 PC의 Codex 로컬 작업 환경. 선생님은 윈도우와 맥을 모두 보유하지만 각 기기의 사양은 아직 모른다. 실제 현재 환경을 먼저 확인한다.
- 첫 흐름: PC 사양과 기존 환경 확인 → LM Studio 및 모델 시험 → 가상 자료로 성적 분석 도구. 영어 수업 도구의 우선순위는 선생님과 진행하면서 조정할 수 있다.
- 아직 LM Studio, Whisper, 모델, 앱 설치·실행 여부는 확인하지 않았다. 기능 구현이나 동시 접속 성능도 검증되지 않았다.
- 모델, 음성 도구, 언어·프레임워크, 저장 방식, 사용 인원, 배포 방식은 확정하지 않았다. 기기 사양과 목적을 확인한 뒤 선택한다.
- 로컬 AI는 데이터가 외부에 나가지 않도록 설계할 가능성을 주지만, 실제 앱·음성 인식·동기화·로그·네트워크 설정까지 확인하기 전에는 외부 전송이 없다고 단정하지 않는다.

## 만들고 싶은 도구

### 1. 교사 성적 분석실

- 내신과 모의고사의 가상 자료를 읽고 시험별·학생별 변화, 가능한 영역·문항별 분석과 그래프를 제공한다. 실제 파일 형식과 필요한 분석은 추후 확인한다.
- 계산은 검증 가능한 코드가 맡고, AI는 계산된 근거를 토대로 해석·상담 초안을 돕는다. 데이터에 없는 원인이나 학생 특성을 단정하지 않는다.
- 내신과 모의고사는 각각의 의미를 살려 보여 주며 단순 합산하지 않는다. 데이터 형식, 결시·누락, 산식, 결과의 한계를 명시한다.
- 생기부 문구 자동 작성은 확정 기능이 아니다. 시험 점수만으로 관찰하지 않은 활동이나 태도를 만들어 내지 않으며, 필요 시 별도 교육적·기재 지침 검토를 거친다.

### 2. 영어 쓰기 코치

- 학생 초안 → 선택한 영역 피드백 → 단계별 힌트 → 학생 수정 → 수정 이유와 성찰.
- 학생이 의미 전달, 글의 구조, 문법, 어휘 등 점검 영역을 선택할 수 있다. 정답 제공 시점과 도움의 정도를 조절하고 원래 뜻을 보존한다.
- AI의 피드백이 틀릴 수 있으므로 교사와 학생이 확인할 수 있게 한다. 저장과 과정 기록은 사용 환경과 개인정보 관리에 맞춰 결정한다.

### 3. 영어 대화와 피드백

- 상황과 수준을 선택하고 영어 대화를 연습한다. 막혔을 때 힌트를 선택하고, 대화 후 표현과 다시 말하기를 검토한다.
- 우선 말하기가 끝나면 인식하고 답하는 차례별 대화를 목표로 시험한다. 지연이 적은 동시 실시간 대화는 별도 성능 검증 후 판단한다.
- 음성 인식 결과는 참고 자료이며, 인식 실패를 곧바로 발음 오류로 판단하거나 자동 점수화하지 않는다.

### 4. 탐구 설계 도우미

- 관심사 → 탐구 질문 → 범위 → 자료·방법 → 판단 기준 → 한계 → 학생의 최종 선택.
- 질문과 선택지를 통해 학생이 설계하도록 돕고, AI 제안을 수용·수정·거절한 이유를 기록하도록 한다. 영어 수업용과 교과 공통용 확장을 고려한다.

### 5. 토크나이저 탐구

- OpenAI 토크나이저와 로컬 모델의 토크나이저를 각각 확인해 문장의 토큰 분할을 시각화·비교한다.
- 모델마다 분할이 다르므로 OpenAI 토크나이저의 수치를 다른 모델의 정확한 토큰 수로 취급하지 않는다. AI 리터러시 탐구에 활용한다.

### 6. Whisper와 영어 말하기

- OpenAI의 공개 Whisper 모델 등 로컬 음성 인식으로 영어 녹음을 텍스트로 옮기고 학생이 수정할 수 있게 한다.
- 로컬 실행과 클라우드 API는 다른 방식이다. 실제 구현의 데이터 경로, 설치 조건, 언어 인식 품질과 속도를 시험한다.

### 7. 모둠 더빙·영상 제작

- 장면 선정 → 영어 대본 작성 → AI 힌트 → 역할 분담 → 학생 직접 녹음 → 시간 맞추기 → 자막·영상 저장 → 감상·성찰.
- 처음에는 녹음과 대본 확인 등 작은 기능부터 만들고, 영상 합성과 공동 편집은 별도로 확장한다. 영상·음성 편집은 LM Studio 자체 기능이 아니며 별도 도구가 필요하다.
- 직접 만든 영상이나 사용 권한이 확인된 자료를 우선 사용하고, 공개·배포 범위와 학생 음성 사용에 관한 학교 지침을 확인한다.

### 8. 본인 목소리 기반 음성 합성 실험

- 학생이 직접 녹음한 음성을 재생하는 것과, 참고 음성으로 새 문장을 합성하는 것은 다르다. 합성은 별도 모델·실행 환경·라이선스 검토가 필요하다.
- 처음에는 선생님 자신의 목소리로 품질과 실행 성능을 시험한다. 학생의 경우 충분한 설명과 본인 동의, 필요한 보호자·학교 절차, 거부 및 대안, 접근 제한, 보관·삭제를 설계한 뒤 검토한다. 다른 사람 목소리 무단 복제 금지.
- 합성 음성만으로 실제 영어 말하기 연습을 대체하지 않도록 직접 녹음과 비교 활동을 고려한다.

### 9. 학생 AI 제작실

- 학생이 목적과 역할, 지침을 만들고 동료와 시험하며 오류를 찾아 개선한다.
- 역할을 지정한 챗봇에서 시작해 필요할 때만 자료 검색이나 도구 호출을 추가한다. 자유로운 도구 실행과 학생 성적 자료에 대한 접근은 기본으로 주지 않는다.

### 10. 학교 워크스페이스

- 처음에는 교사 개인 사용, 이후 동료 교사와 소규모 시험, 필요할 경우 학급·학교 공유를 검토한다.
- 독립 설치와 학교 내 공용 서버는 다른 방식이다. 브라우저로 여러 명이 쓰는 경우 인증, 학생별 권한, 저장 위치, 학교망 접근, 동시 사용 속도, 장애 대응을 따로 검증한다.
- 교사의 성적 분석 자료와 학생 제작·수업 공간은 논리적·실질적으로 분리하고, 학생이 성적 자료에 접근하지 못하도록 한다.

## 개발과 검증 원칙

1. 실제 데이터 없이 가상 성적·가상 학생 자료로 시작한다. 학생 개인정보는 학교 방침과 처리 적합성 확인 전 사용하지 않는다.
2. AI 모델·서버·앱·데이터 저장·음성 및 영상 기능의 역할을 구분하고, 데이터가 어디로 이동하고 저장되는지 명시한다. 클라우드 서비스나 인터넷 의존성이 있으면 숨기지 않는다.
3. 모델을 내려받아 로컬에서 사용하더라도 업데이트, 연결된 서비스, 브라우저 음성 인식, 동기화 폴더, 로그 등은 별도로 점검한다. 네트워크 공유 시 인증과 권한을 검토한다.
4. 가상 자료에서 입력 → 계산·AI 응답 → 저장 → 다시 열기 → 내보내기의 실제 흐름을 시험한다. 계산값은 독립적으로 대조한다. 가능한 범위와 미검증 항목을 분명히 보고한다.
5. 동료 교사에게 제공할 때는 OS, 사양, 설치 권한, 모델 다운로드, 라이선스, 사용·종료·오류 해결 안내를 확인한다. 다른 컴퓨터에서 재현 테스트하기 전 보편적 작동을 보장하지 않는다.
6. 디자인은 읽기 쉬운 정보 구조와 완성도 있는 화면을 우선한다. 선생님은 개성 있는 에디토리얼 타이포그래피를 좋아하고 인디 핑크·네이비 계열을 선호한 적이 있다. 프로젝트에 맞는 실제 디자인은 별도로 확인하며 녹색 중심을 기본으로 가정하지 않는다.
7. 핵심 결정, 남은 작업, 테스트 결과와 정확한 파일 경로를 프로젝트 문서에 남긴다. 추측을 확인된 사실처럼 기록하지 않는다.

## 처음 Codex에서 할 일

1. 현재 실행 환경이 실제 선생님의 PC인지 확인한다. 운영체제, RAM, CPU, GPU, 여유 저장 공간, 설치 권한, 기존 LM Studio/Python 등을 읽기 위주로 조사한다. 민감한 개인 파일은 필요 없이 열지 않는다.
2. 결과를 쉬운 말로 설명하고, 로컬 AI·Whisper·영상 기능의 현실적인 가능성과 제한을 구분한다. 모델 추천은 사양과 현재 공식 자료를 확인한 뒤 제안한다.
3. 프로젝트 폴더를 마련하고 이 문서를 보존한다. 현재 진행 상황과 다음 행동을 별도 파일에 정리한다.
4. 설치는 선생님의 목표와 실행 환경에 맞게 진행하고, 모델 다운로드·실행·연결이 실제로 성공했는지 확인한다. 실패 시 오류를 그대로 설명하고 우회 가능한 대안을 찾는다.
5. 이후 가상 데이터 기반 성적 분석의 최소 기능을 설계·구현하고 계산을 검증한다. 실제 성적이나 학생 음성은 요청하지 않는다.
